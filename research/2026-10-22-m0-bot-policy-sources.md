## APIs and state that must not cross the bot boundary

- Do not port `AI::GetRelationHegemony` as a fair relation oracle: it reads hidden general names from Room tags to derive actual kingdoms. [ai.cpp:54–75](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/ai.cpp#L54-L75).
- Do not share `sgs.ais`, `sgs.card_lack`, loyalty/intention or another AI's friends/enemies tables between web actors. Native state includes process-level tables and cross-AI reads. Legitimate observations from public responses may inform a **per-seat** inference record, whose evidence and restore identity are explicit. [smart-ai.lua:43–51](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/lua/ai/smart-ai.lua#L43-L51), [smart-ai.lua:98](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/lua/ai/smart-ai.lua#L98), [smart-ai.lua:2114–2149](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/lua/ai/smart-ai.lua#L2114-L2149).
- Raw `self.room`, `Global_room`, card piles, server tags and other actors' hands/general objects are not observation APIs. Conversely, native `getKnownCard` filters using `cardIsVisible`; this demonstrates that native code also has deliberate knowledge guards. Do not claim every native helper cheats. [smart-ai.lua:4686–4708](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/lua/ai/smart-ai.lua#L4686-L4708).
- A list of legal offers can itself leak if produced from forbidden hidden input. Validate the observation/offer builder independently of the pure chooser. The chooser receives opaque current choice IDs and only actor-visible typed semantics, not a closure referencing the full Room or label-string parsing as an undocumented legality oracle.

## Smallest useful TypeScript experiment

Use one pure decision function of serialized observation, current legal offers, per-seat memory and a versioned bot seed. Return an offered opaque choice ID (or legal decline), plus updated per-seat memory. The session retains actor authentication, request identity, revision/idempotency and controller generation; the bot cannot choose an actor or reset a deadline. Use the same admission/resume path as a human and separately label any fixture catalogue/legality authority.

Begin with independently worked tactical fixtures: answer one plain harmful Slash with an offered Jink; rescue self using an offered legal card; discard Slash rather than the sole Peach; decline an unnecessary/protective-opponent Nullification; choose a legally available favorable target from public HP and known relation. Add skill/choice/reveal fixtures only where current child operations actually execute. A chooser-only test does not establish an executed engine family.

Required measurements are still future execution: stable choice under hidden-state perturbation with identical actor observation/offers/history/seed; separately stable offered views where hidden changes must be unobservable; rejection of delayed bot work after human takeover; one acceptance in a human/bot race; serialized per-seat memory restore; versioned tactical outcomes and CPU/time/RAM. Report unexecuted prompt families explicitly. None of the above demonstrates competitive play, all-package support or five-room capacity.

TypeScript is the smallest first experiment because the engine/admission already use it. Embedding native Lua would also require replacing Room/QVariant/QList/card-object callbacks, discovery and shared state with actor-safe APIs; simply embedding the native script is not a comparable safe policy. This is a source-derived compatibility assessment, not a measured Lua-versus-TypeScript performance verdict.
