Source modules are `ask-card-use.ts`, `retrial.ts` and `retrial-skill.ts` under `src/game/hegemony/`; regressions use actual scheduler dispatch/resume and physical movement. ## Selection and acquisition

`createAskCardNoneOperation` and `createAskCardDiscardOperation` register `ask-card-none` and `ask-card-discard`. They share the private room-wide provided slot, conversion, continuing/retry and wrapped synchronization with [Use/Response acquisition](direct-card-use.md). Both set unknown room reason and suppress CardAsked. None bypasses limitation checks, returns the validated response and leaves materials alone. Its rules need no table/discard/reveal/use/after adapters.

Discard keeps its method-specific admission/limitation policy. Before ChoiceMade, its accepted-notification adapter owns the native request-skill discard log/notice when request skillName is nonempty. Then move current post-ChoiceMade materials directly to discard with THROW(actor). It has no skill/general reason metadata or table intermediate. It does not call throwCard, run the later owned-card-skill notice or emit ordinary response/use/finish/reveal/after events. Provision and retrial do not suppress this discard. A zero-material response still returns without inventing physical payment.

Optional request `isRetrial=true` suppresses CardAsked and ordinary Use/Response execution, logs, skill notices, reveal and after-hooks. Wrapped synchronization, conversion, ChoiceMade and validated return remain. Retry retains retrial and resets skillName/provision to native defaults. MethodUse still forbids the bare Slash pattern. Accepted notices for selection/retrial carry method/request-skill/retrial context so the delivery adapter can apply the right synchronization/log policy; ordinary packets retain their prior shape. Admission, transport and human/AI parsing remain private adapters.

## Shared judgment and result

`RetrialGame.judges` stores pending or ready judgments by stable private ID. Operation/event payloads reference that ID, retaining shared identity through nested execution and JSON restore. `JudgeState` has who/card, pattern/patterns, good, reason, time_consuming, negative, play_animation and an explicit unknown/good/bad result cache. `readJudge` remains strict about nonnull who/card. Part 4ac adds `PendingJudgeState` with nullable card and a separate `readPendingJudge`, used by the actual [Room judgment owner](judgment.md).

`createJudgeResultOperation` registers `update-judge-result`. It asks a copied-state pattern matcher about the current judgment and stores good exactly when `judge.good === matches`. `judgeIsGood` requires a known cache. `judgeIsEffected` inverts good only when negative is set. Pattern grammar is an adapter; comparison, cache and negative semantics are implemented. Changing a judgment card does not implicitly refresh its cached result.

## Core replacement

`createRetrialOperation` registers `retrial` with actor, judge ID, nullable incoming registered card, skillName and exchange. Null card returns before judgment lookup. A real replacement validates the ready judgment, physical locations, distinct new/old effective IDs and canonical physical reference before eager changes. A wrapped card uses its physical ID; a virtual card uses its first material. Missing material, duplicate IDs, invalid canonical lookup and ambiguous location reject safely rather than reproducing native assertions/null dereferences.

Capture incoming effective-ID owner/hand, old judge card, destinations and movement records. Assign the canonical physical incoming card to the shared judgment before changed-judge notification. Then run one real two-record atomic movement with force visibility true: new effective ID into the captured judged player's judge zone using RETRIAL(actor,skill); old effective ID into responder hand using OVERRIDE(actor,skill) on exchange, otherwise discard using JUDGEDONE(actor) without skill. Extra incoming virtual materials are not moved by this core or automatically cleaned up.

Only when the captured incoming owner equals actor, emit CardResponded at actor after movement: incoming parsed/virtual card, the same captured judgment's then-current who, isUse=false, isRetrial=true, captured effective-ID hand provenance and null data. Child mutation/consumption does not replace captured moves, gate or incoming identity. The original response descriptor is refreshed from private metadata and current resource-ledger flags. Core replacement never recomputes the result.

## Guicai and Guidao

`createRetrialSkill` creates an actual AskForRetrial TriggerSkill for either package skill at native default priority 3. The current living event target is the responder; a private eligibility adapter supplies enabled skill ownership/slot/shown metadata. Part 4ac supplies the actual [Room judgment actor loop](judgment.md); representative Guicai/Guidao composition now begins with a pending judgment and actual draw.

Cost requests actual `ask-card-response` with retrial true, empty request skillName and provision false. Guicai pattern is `..`; Guidao is `.|black`. The prompt snapshots who, package skill, reason and old effective ID. After validated acquisition, package notices run; capture hand provenance from the effective ID only, then move all current materials to table using RESPONSE(actor,package skill). Package movement keeps forceVisible=false and deterministic open=true for the public table. Native notification copies make table cards public; native server-side `CardsMoveStruct.open` is uninitialized on this path. This JSON normalization does not claim parity with that uninitialized event boolean.

Emit the package CardResponded with isRetrial=false, original event data and the cost-captured judgment's current who. Even if consumed or rewritten, serialize the original returned identity after this event, using current metadata/resource flags, and push its string to the actor's private `guicai_cards` or `guidao_cards` LIFO stack. Null acquisition returns failed cost without pushing. Scheduler successful-cost generic reveal/Huashen runs next through its explicit reveal adapter, once across suspension; this is distinct from the ordinary card reveal suppressed during retrial acquisition.

Effect pops and persists the string before parsing. Empty stack or parse-null returns false without replacement. Otherwise resolve the current effect event's judge ID, run actual core replacement (Guicai nonexchange, Guidao exchange), then actual result recomputation, and return false. Nested skills use the per-actor/per-skill stack. The usual cost leaves incoming cards on table and therefore suppresses the core's extra owned-card response; a child that changes ownership before replacement can make that response occur under its captured gate.

## Persistence, adapters and exclusions

Shared decoders resolve registered responses without changing reference identity and refresh flags from the resource ledger. Scheduler operation/event children, package notices, acquisition, generic reveal and actual movement can suspend and restore JSON. Prompt actor/generation/registry validation prevents duplicate work. Interruptions keep eager paid state and freeze frames under current scheduler policy; native unwind/rollback is not added.

Real implementations cover selection ownership, replacement, result and representative cost/reveal/effect composition. Tests supply explicit adapters for catalogue/skill/pattern admission, current metadata/canonical lookup, matcher grammar, codec, eligibility and notification/reveal delivery. Those fixtures do not establish enabled package legality or production behavior. Part 4ac supplies [Room::judge and its GameRule stages](judgment.md) plus actual [draw/recycling/reservations](draw-pile.md). Part 4ab.4 supplies [SinglePeach-to-Room composition](single-peach.md). Part 4ad adds [batch/player drawing and Draw phase](card-drawing.md). Part 4ae adds [global GameStart and initial drawing](game-start.md) plus [luck-card state/manual transfer](luck-cards.md). Huanshi/Midao/Kongyun wrappers, complete startup/package authority, complete parser/catalogue, native unwind, application/network/UI/bots and complete-match parity remain separate. Production still registers Standard2013.
