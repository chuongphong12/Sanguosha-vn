## TurnStart and face-up authority

TurnStartGame reuses the same GeneralGame/PhaseGame Room and adds one faceUp boolean map. createTurnStartRule is priority zero; its turn-start child consumes SkipGameRule before resolving currentPlayer. A higher-priority consumed event never enters it. The event target does not replace the currentPlayer captured by the GameRule effect. Native [TurnStart](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L332-L394) establishes the order.

FirstRound becomes false and Global_FirstRound is set before its notice. Then separator, Global_TurnCount increment/notice and public hand counts for every registered actor, including dead seats. Counts derive from physical hand zones; no card IDs are in that notice. Capture the actor at effect entry; later presentation children do not reassign that local actor. Required play-phases/free-chain children fail explicitly when absent. Counters, flags and properties commit before their notices and are not replayed on resume.

A face-down actor, including a dead actor, loses Global_FirstRound, invokes real turn-over and then real free-chain without playing phases. turn-over flips the same faceUp map, publishes the property, logs its live face-up value and emits actual TurnedOver, following [ServerPlayer](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.cpp#L1037-L1050). A face-up living actor gains Global_RoundCount then calls actual play-phases with the default sequence. A face-up dead actor does neither. Debug-only playNormally is not enabled.

## Optional BattleRoyal

Factory configuration captures a boolean and native mode playerCount2–10 plus a presentation operation factory. It does not enable BattleRoyal in an existing application. When configured and not entered, native livingPlayers count must be below5 for mode counts above7, otherwise below4. A pair of shown friends blocks entry; hidden same-kingdom facts alone do not. The implementation uses existing hasShownGeneral/areGeneralFriends authorities, not a viewer projection.

Real enter-battle-royal orders lightbox → log → tag true → battle-start notice → captured living-player GlobalBattleRoyalMode marks, as [Room](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L450-L468). Presentation remains explicit. Captured actor lists and the next index persist before suspension; a new interruption keeps earlier tag/mark effects. This adds core transition ownership, not every BattleRoyal card/package rule or UI.

## Normal and extra turns

NormalTurnGame adds one private turnOrder cursor: regular/anchor-null or extra/regular-anchor. normal-turn-step is a trusted scheduler root with at most one TurnStart per invocation. A regular step captures currentPlayer as anchor before emitting actual TurnStart. Each extra step reads live ExtraTurnList, removes the first name before lookup/TurnStart, and resolves native displayed-head/object-name alternatives in living-player order. Unknown/dead matches are skipped. An empty array is removed on the next step; absent/null tags remain absent/null. Nested grants remain live. These are explicit cooperative root boundaries around native [normal loop](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/roomthread.cpp#L112-L151).

Once extras drain, next normal actor comes from the original regular anchor, using fixed seatOrder and alive with [getNextAlive(1,false)](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.cpp#L2272-L2305); removed living actors remain eligible. No-alive fallback retains the anchor. Compare live seats of next/anchor; a wrap captures current-first deathOrder and invokes actual typed clear-player-marks(-round), including dead seats. Capture next before mark children; later life/seat changes do not reselect it. Only after cleanup set currentPlayer and reset the cursor. A terminal gameResult stops the normal step before another TurnStart or extra consumption.

## Recovery after explicit unwind

recover-normal-turn is an internal trusted root. The caller must first complete scheduler unwind and classify the reason as TurnBroken. It captures currentPlayer, emits actual TurnBroken, captures next from that player's live next-alive relation, then if the player's phase is active calls only phase-cleanup(EventPhaseEnd) with its real SkipGameRule guard. It then invokes actual change-phase using the player's later phase as from and fixed NotActive as to. Finally set captured next/reset the normal cursor. No full EventPhaseEnd trigger or package End listeners run again; no round-wrap cleanup is invented in this recovery path. [Native catch](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/roomthread.cpp#L153-L180) owns this order.

If recovery interrupts again, its continuation is abandoned through real unwind; a later authorized TurnBroken recovery starts from current Room facts. Earlier marks/history/movement remain. Neither root clears interruption/frames itself or automatically recovers StageChange/GameFinished. Aggregate reason classification, startup unsupported-boundary faults, terminal ownership, root/save validation, pump scheduling and filtered battle projection belong to M1.3.5. Direct library dispatch is not a player command interface.
