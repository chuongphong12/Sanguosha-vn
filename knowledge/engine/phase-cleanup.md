## Phase GameRule owner

[phase-cleanup](https://github.com/chuongphong12/Sanguosha-vn/blob/652056e30eafd4faa4198e34d86fc9d33adec0c4/src/game/hegemony/phase-cleanup.ts) is the priority-zero bridge for Start/End/Changing and the trusted direct effect entry for later recovery. It consumes SkipGameRule once at effect entry before cleanup; a higher-priority consumed event never enters this rule. Null targets have no phase body. Direct effect entry runs only this GameRule effect, not all package End listeners. Native [GameRule phases](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L392-L521) defines the order.

- Changing broadcasts pushPile history, then clears positive numeric -PhaseClear marks for a captured current-first all-player list. Read the requested destination afterward. Entering Play clears that actor's history; Start clears Analeptic. Entering NotActive captures a fresh all-player list for positive numeric -Clear marks, then processes pending ImperialOrder. These numeric passes do not clear typed list marks of the same name.
- End clears Play history. Finish clears Analeptic and sets multi_kill_count to zero for the native current alive-player list. Then capture all players including dead and run typed -phase cleanup. Existing allPlayers preserves the native null-current quirk: it returns all registered actors in that case.
- NotActive Start captures all players in current-first order. Per actor: clear flags and notify; if drank is positive, log then zero/notify; clear typed -turn marks; clear single-turn limitations and notify; reset removed if true, send its property notice and emit actual RemoveStateChanged; only then read/delete TurnSkillsFor and build the native unsuffixed head-detach list. Removal listeners can change that live list or interrupt. A reset event's consumed result does not cancel the void-method tail. Already-false removed emits no reset event.

New interruptions preserve eager changes and remaining tags/actors. No catch or unconditional finally is invented for these native methods. Required mark, skill, filter and ImperialOrder children must be registered; missing composition fails explicitly. Captured player lists, per-type names and serial stages persist through JSON/cooperative yields; completed mutation/notification/event stages do not replay.
