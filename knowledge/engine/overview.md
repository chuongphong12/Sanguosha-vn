# Engine boundaries

This snapshot describes the web code at the game revision in [source metadata](../source-baseline.json), against the [selected native source](../rules/source-authority.md). Quốc Chiến is the target game model. The running web application still registers the legacy `TqsGame`: `server/server.ts` and `src/client/MatchClient.ts` import it, and `src/game/TqsGame.ts` names it `tam-quoc-sat-standard-2013`. The isolated library checkpoints do not perform the runtime cutover.

The new `src/game/hegemony/` modules provide paired setup and independently registered normalized scheduler operations. `src/game/hegemony/types.ts` defines setup status as `selecting-generals | ready`; `src/game/hegemony/index.ts` explicitly states that **ready is not a playable match**. No implemented library operation should be presented as an enabled player command without a production action, legality and privacy adapter.

The separate [local session experiment](prototype-session.md) now composes real draw/Play/Room/Slash/MethodUse/Jink/movement/damage operations under staged Master, with private prompt and process-crash recovery checks. It uses synthetic fixture authorities, two seats, one Slash allowance and fixture ArcheryAttack; it does not register a playable production mode. Its earlier [checkpoint](../reviews/2026-10-23-hegemony-m0-pending-jink.md) and earlier [service-clock checkpoint](../reviews/2026-10-26-hegemony-m0-service-clocks.md) record execution evidence. Independent persisted prompt/disconnect clocks, room recovery grace and automatic pending Jink/cancel decisions now exist in this fixture; timing precision, other request families, production multi-seat lifecycle, full bot turns and hosted-provider storage remain open. The [separate local PostgreSQL proof](../reviews/2026-10-26-hegemony-m0-postgres.md) now exercises SQL persistence/recovery and writer fencing through the same session.


The [explicit-Leave bot handoff](../reviews/2026-10-26-hegemony-m0-permanent-bot.md) now preserves the fixture character and revokes all departed-human rights, with human-only presence/grace accounting and file/SQL recovery evidence. Full-turn bots and production multi-seat integration remain separate. The [MethodResponse slice](../reviews/2026-10-27-hegemony-m0-method-response.md) additionally executes fixture ArcheryAttack with real CardResponded/movement/damage; response-v4 rejects old fixture saves. Nullification remains disabled, and this is not a complete package.

The later [M1.1 internal match module](match-authority.md) adds a one-time setup-to-Room handoff, private projections and version/settings-bound JSON continuation. Real global GameStart/dealing is exercised for 2–10 seats with internal fixture content; accepted/declined luck composition is exercised through a two-seat collection adapter. The later [M1.2 startup owner](startup-owner.md) adds initial winner/global/player startup with separate static global/full tables, schema-v2 cursor and completed-root recovery. This module is not wired to production or the M0 socket/store coordinator; full phase/turn ownership and native interruption cleanup remain open.

## Shared invariants

- Authoritative state and continuations are JSON data. Registries, callbacks and package code live outside persisted state and are version-pinned by the scheduler.
- Physical card IDs have one physical location. Reference identity, current string keys, wrapper faces and movement notification groups remain distinct concepts.
- Native local snapshots and mutable event data often differ. Preserve captured source, recipient, material and loop snapshots exactly where the owning caller does; later child rewrites do not universally replace them.
- Preflight rejects malformed selected inputs before allocating a frame. Late boundary errors preserve earlier committed children and eager state. This is not a rollback transaction.
- Default profiles freeze turn-broken, stage-change and game-over with eager effects. [Opt-in unwind/yield](scheduler-unwind.md) and [M1.3.2 protected core catches](core-interruption-cleanup.md) implement bounded library cleanup. Phase/turn ownership and enabled application integration remain subsequent gates.
- Private head/deputy identities, scenario authority, raw card ledgers, resources, event payloads, frames and operation completions are not client state. The setup projection is not a complete battle projection.

Sources: the exported interfaces and dispatch/resume implementation in `scheduler.ts`, authoritative types in `movement.ts`, `card-resources.ts`, `death.ts` and `general-identity.ts`, and projection in `index.ts` at this snapshot.

## Remaining integration gates

Concrete package/catalog discovery and its live legality authorities, complete Room/RoomThread startup, per-player startup package registration and full phase/turn policy, movement visibility notifications, equipment installation/uninstallation, general removal/transformation, full older GameRule guard integration, exception unwind and native mutable pointer/subcard adapters remain incomplete. The normalized direct request family now covers Use/Response/None/Discard and retrial acquisition, with representative Guicai/Guidao composition. Part 4ac adds actual Room judgment and draw/recycle/reservation with a versioned portable RNG; Part 4ad adds actual batch/player drawing, fill-hand/token composition and the Draw-phase owner with three real free-chain boundaries; Part 4ae adds actual global GameStart, limited marks/private view/FirstRound, initial drawing and luck-card state/manual transfer, with explicit catalogue/broadcast/private delivery adapters; other package callers still need integration. SkillCard onUse composes shared GameRule/resources/effects. Package dispatch, live card/reference ancestry and reveal/transport remain explicit authorities. ImperialOrder's pending diversion tags do not implement its NotActive effects. Setup-to-battle private authority synchronization, filtered battle views, authoritative routing, UI/AI/network migration, native differential tests and Standard runtime retirement remain required before production cutover.

Evidence: external adapter interfaces across the modules above; absence of battle status in setup types; unchanged `TqsGame` production registration. A later implementation must narrow this list using inspected code and new validation, never by carrying forward a checkpoint's old “next seam” paragraph.
