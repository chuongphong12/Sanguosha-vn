## Native judgment state before drawing

JudgeStruct defaults are who=null, card=null, pattern=".", good=true, time_consuming=false, negative=false, play_animation=true and cached result UNKNOWN; QString/QStringList fields give empty reason/patterns. Room::judge requires nonnull who but does not require a preexisting card or known result and does not reject a dead who. The unknown result asserts if isGood/isBad/isEffected is used before a handler initializes it. Source: [structs.cpp:196–231](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.cpp#L196-L231), [structs.h:388–417](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L388-L417) and [room.cpp:469–478](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L469-L478).

Result calculation compares `good == ExpPattern(pattern).match(who, card)` and caches GOOD/BAD. Negative changes isEffected's interpretation; it does not change that cache. The separate isGood(card) computes a candidate result without writing the cache. time_consuming is carried by the structure but is not read by the Room judge or three GameRule cases below. Do not invent a delay policy from its name. Source: [structs.cpp:202–231](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.cpp#L202-L231), [room.cpp:469–502](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L469-L502), [gamerule.cpp:932–982](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L932-L982).

## Room owner: captured original versus mutable event pointer

Room captures the original JudgeStruct address as judge_star and initializes a shared QVariant containing that pointer. It increments the current integer `judge` room tag, emits StartJudge at original judge's current who, then takes a fresh getAllPlayers snapshot. Each actor receives AskForRetrial using the same mutable data variable. Consumption of an AskForRetrial breaks only this actor iteration. Room then emits FinishRetrial at the original judgment's current who, decrements the **latest** judge tag, emits FinishJudge at the original judgment's current who, then optionally logs JudgeEffected/JudgeFailure from that original judgment's current cached interpretation, who and reason. StartJudge, FinishRetrial and FinishJudge consumption do not cancel the owner's subsequent stages. Source: [room.cpp:469–502](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L469-L502).

These are two identities: the owner's captured original pointer and the mutable event data's current pointer. A listener can replace event data; subsequent GameRule/retrial listeners see the replacement, while Room's targets/final summary still read the captured original. Mutating fields on either shared object is distinct from replacing the event reference. A stable-ID JSON model must preserve both rather than copying the original into every event or letting a rewritten event ID replace the owner's captured ID. The tag decrement is not restoration of a saved entry value. Room has no local try/finally/catch around these stages; interruption can occur before decrement. Source: [room.cpp:473–500](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L473-L500).

getAllPlayers defaults include_dead=false. When current is registered, it rotates registration order to current first and filters current alive state. When current is null or absent from registration, it returns raw registration including dead seats, regardless of that default. Room::judge snapshots this list **after** StartJudge and does no later per-actor alive recheck. Changes during later AskForRetrial events do not reorder the captured list; individual skill eligibility can still reject dead actors. Source: [room.cpp:192–215](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L192-L215), [room.h:89](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.h#L89) and [room.cpp:480–484](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L480-L484).

## Priority-zero GameRule stages

GameRule registers StartJudge/FinishRetrial/FinishJudge and always provides its rule occurrence at priority zero. Its effect consumes one-shot SkipGameRule before the null-target/global branch. Earlier event consumption can prevent this rule from running, but Room still advances according to its owner contract; a handler that consumes StartJudge must establish usable judgment state itself if later consumers require it. Safe JSON validation should reject invalid pending dereferences rather than imitate native assertions or silently draw another card after consumption. Source: [gamerule.cpp:115–157](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L115-L157), [262–271](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L262-L271) and [Room sequence](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L478-L490).

### StartJudge

The rule calls `room->drawCard()` first, then obtains JudgeStruct* from the **current event data after that call**. It assigns the canonical Sanguosha physical card, sends InitialJudge, moves that card to the judgment's current who in PlaceJudge with force visibility true, and only then updates that same captured judgment's result. The reason is JUDGE with actor=who, empty target/skill, eventName=judge.reason. Movement precedes cached result update, so observers can see the newly assigned card with an old/unknown cache. The default draw source uses from_up=true. Source: [gamerule.cpp:932–947](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L932-L947), [reason constructors, structs.h:146–164](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L146-L164) and [room.h:152](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.h#L152).

### FinishRetrial

The rule reads the current event judgment pointer and logs JudgeResult using **event player** as source and that judgment card's effective ID. For each candidate in patterns, in list order, match `ExpPattern(candidate).match(eventPlayer, judge.card)`; the first match replaces judge.pattern and stops. It does **not** recompute the result after changing pattern. Thus pattern and cached GOOD/BAD can intentionally reflect different evaluation stages. When play_animation is true, sendJudgeResult reports current card ID, cached isEffected, judge.who and reason, followed by the configured long judge delay. Source: [gamerule.cpp:949–972](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L949-L972) and [room.cpp:504–512](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L504-L512).

### FinishJudge

Read the current event judgment pointer. Only if its current effective card ID is globally in PlaceJudge, discard it when reason is not exactly `luoshen` **or cached isBad is true**. A good Luoshen card remains even if negative=true makes isEffected false. A card already taken into another place is not discarded again. The move is JUDGEDONE with actor=judge.who, empty skill, eventName=judge.reason, force visibility true. This call uses the four-argument reason overload; its last argument is eventName, not skillName. It differs from core retrial's JUDGEDONE(actor) reason with no event name. Source: [gamerule.cpp:974–982](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L974-L982) and [structs.h:146–164](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L146-L164).

## Drawing is a separate real authority

StartJudge uses `drawCard`, not `getNCards(1)`. drawCard emits FetchDrawPileCard at null target before checking pile emptiness, ignores its consumption, swaps piles if the draw list is then empty, and removes the first ID (or last only for explicit from_up=false). getNCards additionally checks requested capacity before any per-card draw, may swap while draw is nonempty, and optionally broadcasts draw-list count. Substituting it changes hooks and timing. Source: [room.cpp:3253–3259](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L3253-L3259) and [515–531](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L515-L531).

The no-data trigger overload creates a fresh default QVariant; normalize its JSON payload to null rather than exposing or sharing the outer judgment payload. The fetch hook may change the pile before drawCard examines it, but its data rewrite/return does not directly select the returned ID. drawCard returns the removed ID without looking up its canonical card or changing owner/place mappings; StartJudge performs canonical lookup afterward. ID zero is valid: Engine::getCard rejects negative/out-of-range values, not zero. Missing canonical identity, negative ID or inconsistent normalized locations can reject safely without treating zero as a nil sentinel. Source: [roomthread.cpp:673–676](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/roomthread.cpp#L673-L676), [room.cpp:3253–3259](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L3253-L3259), [gamerule.cpp:932–936](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L932-L936) and [engine.cpp:555–572](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/engine.cpp#L555-L572).

swapPile first calls gameOver(".") if both piles are empty. It then increments the latest SwapPile count, computes Config PileSwappingLimitation (default 5) plus one and ends the game only when the resulting positive limit equals the incremented count. It shuffles discard, changes each card mapping to null-owner DrawPile, appends the shuffled list to any remaining draw cards, clears discard and sends reset/update-pile notices. qShuffle is a forward Fisher–Yates loop with qrand()%remaining. Seed, RNG stream and configuration version are actual authorities; a deterministic fixture permutation does not establish native random conformance. Source: [room.cpp:2554–2576](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2554-L2576) and [util.h:31–39](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/util.h#L31-L39).

gameOver is terminal: after its eager game_finished state and notifications it throws GameFinished. Both-empty therefore stops before incrementing SwapPile; a reached swap limit stops after increment but before shuffle/mapping/notices. A normalized terminal child must prevent its parent from continuing even if a notification callback returns normally. swapPile itself does not reset card flags/wrappers or call movement/lose/get hooks; setCardMapping only writes owner and place maps, normalizing DrawPileBottom to DrawPile. Reset-pile notification precedes update-pile notification after discard is cleared. Source: [gameOver, room.cpp:544–602](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L544-L602), [swapPile:2554–2576](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2554-L2576) and [mapping:6574–6578](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6574-L6578).

## Phase and package boundaries

The Judge phase snapshots a player's judging-area delayed tricks, processes them last-first while that player is alive, moves a trick to table, runs cardEffect and then onNullified if needed. It does not itself contain the complete Room judge call; concrete effects/skills invoke judging. Room judge is also used outside Judge phase, e.g. Ganglie's damage-triggered handler constructs a pending JudgeStruct and calls room->judge, then reads the chosen pattern. Implementing Room judging does not establish the phase loop or every judgment-calling package. Source: [gamerule.cpp:175–188](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L175-L188) and [standard-wei-generals.cpp:208–234](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/package/standard-wei-generals.cpp#L208-L234). No new package handler is proposed by this note.

## Proposed bounded acceptance matrix

1. **Pending entry and shared identity:** accept known who with null card/unknown result, reject invalid native-assert inputs safely, allow a dead judged player; preserve original owner ID separately from rewritten event judge IDs and shared field mutations. Existing ready-only retrial validation must still reject unusable pending cards.
2. **Owner sequence:** actual StartJudge → fixed AskForRetrial actor loop → FinishRetrial → latest counter decrement → FinishJudge → optional final summary. Start/finish consumption ignored by owner; retrial consumption breaks only actor iteration. Nested judges and externally changed counter values must not be overwritten by saved entry state.
3. **Order snapshot:** take getAllPlayers after StartJudge; current registered/null/missing, dead current, actor death after snapshot, current change during actor loop and retrial-consumed break. Do not add an owner-level alive recheck absent from native.
4. **Start rule:** actual draw child or explicitly labelled adapter, card assignment and initial notice before actual JUDGE movement, cache update after movement; event-data judge pointer captured after draw, then retained across movement. Observe empty skill and reason as eventName, force-visible behavior and transient unknown/old result.
5. **Retrial composition:** compose actual Guicai/Guidao cost/reveal/effect and core replacement/result from Part 4ab.3, verifying exactly one initial draw and captured/rewritten judge identities. Registry/metadata/eligibility codecs remain explicit authorities.
6. **Finish result:** first matching alternate pattern uses event target rather than a newly rewritten who, does not recompute cache, sends cached negative-aware result only with play_animation, and preserves the separate post-FinishJudge owner summary decision. No-match keeps prior pattern.
7. **Disposal:** actual current effective-card movement only from a judge place; card already taken skips payment; normal reason discards, bad Luoshen discards, good Luoshen retains, including negative good. Assert JUDGEDONE actor/empty skill/reason eventName rather than reusing core retrial reason blindly.
8. **Expanded draw scope B:** FetchDrawPileCard timing/consumption/null payload, valid ID zero, top versus bottom, empty draw with discard, both empty terminal state before counter increment, reached swap limit after increment/before shuffle, append rather than replace, unchanged flags/no synthetic movement during recycle, reset/update notice order, preserved reservation/physical mapping invariants and reload-safe versioned RNG state. Separate structural shuffle correctness from unproven bitwise Qt stream parity.
9. **Persistence and interruption:** JSON suspension at draw, events, notices, actual initial/retrial/disposal movement and result update; nested judge identity and counter; wrong actor/stale/replayed/registry-mismatched prompts; eager effects/counter frozen on existing scheduler interruption. Native exception-specific unwind and whole-match save compatibility remain separate.

Two scoped alternatives were investigated. Isolated A would compose the Room owner and three real GameRule stages through an explicit serializable draw-provider operation owning fetch/reservation/recycle outside the slice, with no native draw-core parity claim. The user selected **expanded B**: implement actual draw/fetch/recycle/reservation/versioned RNG, validate that layer before Room judging, then compose actual scheduler/retrial/movement/result and Guicai/Guidao skills. Matching, canonical catalogue lookup, notices/animation/delay and skill eligibility remain explicit private adapters. Qt RNG stream equivalence, broad packages and production enablement are not implied by B.
