## getNCards is a distinct batch owner

`getNCards(n, update_pile_number=true, from_up=true)` returns ordered physical IDs; it does not transfer them into a hand, table or another destination. Before the first per-card Fetch hook, when n exceeds the current logical draw-list length, it checks n against draw+discard length. Insufficient total capacity calls terminal gameOver(".") before any swap or fetch. Otherwise it calls swapPile **even when the draw list is nonempty**, appending shuffled discard behind its remaining cards. It then calls actual drawCard(from_up) n times. Only after the entire loop, when update_pile_number is true, it sends one UPDATE_PILE with the latest logical draw-list length. See [room.cpp:515–531](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L515-L531) and [defaults, room.h:139](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.h#L139).

Zero and negative n perform no loop iterations and no capacity/swap/fetch; update=true nevertheless sends the count notice and returns an empty list. Preserve native signed-count behavior while rejecting malformed or out-of-range JSON integers. The capacity check happens once before the loop, not before every fetch. Nested FetchDrawPileCard handlers can later consume/reorder/recycle cards or finish the game; each drawCard still performs its own latest empty-pile check. An interruption or later terminal result retains earlier reserved IDs and suppresses the batch's final success count notice. Source: [getNCards loop](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L518-L528), [drawCard:3253–3259](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L3253-L3259) and [terminal gameOver:544–602](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L544-L602).

Top/bottom applies to **each** actual draw after the batch pre-swap. If draw=[A] and shuffled discard=[B,C], a request for two bottom cards returns C,B and leaves A. Merely repeating drawCard twice without the pre-swap would return A first and change native behavior. update=false suppresses only getNCards's final count notice; actual swapPile reset/update notices remain. Batch state needs a serialized ordered accumulator over the existing draw/reservation owner, not a fixture that supplies the whole result at once. See [getNCards](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L515-L531), [swapPile:2554–2576](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2554-L2576) and [drawCard](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L3253-L3259).

## Three Room drawCards overloads

The single-player overload wraps that pointer in a one-element list. The common-count list overload expands n and from_up into vectors of recipient-list length. Both default reason to empty and from_up to true. The final vector overload defaults reason empty and its direction list empty. It receives players/counts/directions by value, asserts the count list is nonempty, then constructs one eventual movement transaction. Source: [room.cpp:4822–4844](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4822-L4844) and [room.h:374–376](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.h#L374-L376).

For each captured recipient slot, increment the index before any skip. Skip a currently dead player unless reason equals exactly `reform`. There is no removed-player, prohibition, lock or hand-limit guard here. Null pointers are not supported: native dereferences them. Count uses `n_list[min(index,last)]`, so a short count vector repeats its last entry; n<=0 skips this recipient. Direction uses that index only when present, otherwise true; a short direction vector does **not** repeat its last entry. Duplicate recipients are not deduplicated. Invalid pointers/count-list assertions should become explicit normalized validation errors, not guessed native defaults. Source: [room.cpp:4843–4860](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4843-L4860).

Each eligible positive-count slot calls `getNCards(n,false,from_up)` and accumulates its IDs. No hand movement occurs until **all** recipients have acquired their cards. Then one actual `moveCardsAtomic(moves,false)` transfers the accumulated records. A Fetch hook can kill an earlier recipient after that slot's alive check; there is no later owner-level recheck before its reserved IDs move. Hooks can also change later recipients before their turn. A capacity failure for a later recipient retains earlier reservations but prevents the final hand transaction; no invented rollback or earlier per-recipient hand transfer is native. Source: [room.cpp:4845–4870](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4845-L4870).

Movement records have from=null, to=recipient, destination PlaceHand, and DRAW reason with actor=recipient, skillName=request reason and empty eventName. This uses the four-argument CardMoveReason constructor; request reason belongs to **skill**, unlike the judgment reason stored as eventName. Force visibility is false. There is no ordinary drawCards-specific flag or DrawNCards/AfterDrawNCards event. Source: [room.cpp:4862–4870](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4862-L4870) and [reason constructors, structs.h:146–164](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L146-L164).

All-skipped input still calls the actual empty movement transaction. An explicit empty recipient vector with a nonempty count vector reaches that path; an empty common-count recipient list constructs an empty count vector and hits the native assertion. moveCardsSub has no empty-transaction early return: with registered players it still dispatches empty BeforeCardsMove/ConfirmMoveCards and later PreCardsMoveOneTime/CardsMoveOneTime, alongside its notification/delay stages. Reuse the existing real movement semantics rather than replacing this with a silent return. Source: [drawCards:4840–4870](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4840-L4870), [movement entry:5151–5210](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5151-L5210) and [movement tail:5294–5312](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5294-L5312).

## Count notices, flags and privacy belong to the movement child

drawCards itself sends no post-transaction count notice. Its getNCards calls suppress their final notices, although swaps still notify. In the actual atomic movement, BeforeCardsMove consumption can abort before physical transfer. After confirmed records and loss notification, remove source IDs; if any current record comes from DrawPile/Bottom, send UPDATE_PILE **then**, before updateCardsOnLose, target mappings, updateCardsOnGet, arrival notification and destination additions. The final count belongs to this movement owner; adding a synthetic drawCards count duplicates or changes it, especially when movement is consumed or rewritten. Source: [room.cpp:4860–4870](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4860-L4870), [Before/confirm stages:5179–5208](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5179-L5208) and [remove/count/mapping:5210–5252](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5210-L5252).

The ordinary arrival clears each physical card's `visible` flag because forceMoveVisible=false, and the existing hand-get hook can filter wrapped identities for the destination player. Per-recipient notification copies calculate openness: the hand recipient normally sees its own cards while unrelated players do not, subject to native relevant-player/Gongxin and other visibility conditions. The default CardsMoveStruct constructor leaves raw `open` uninitialized. A normalized record's open=false is a deterministic private-draw policy, not equality with an undefined native server-event scalar. Existing normalized movement tests and transport delivery responsibilities must stay explicit. Source: [visible flag/destination:5255–5266](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5255-L5266), [get hook:5746–5775](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5746-L5775), [notification:5777–5812](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5777-L5812) and [constructor, structs.h:252–260](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L252-L260).

## ServerPlayer drawing and fill-hand

ServerPlayer::drawCards forwards directly to the single-player Room overload. fillHandCards first requires alive and target n greater than current hand size, then draws the positive deficit with the supplied reason. This alive guard applies even to reason reform, which Room drawCards otherwise permits for a dead recipient. The deficit is computed once; it is not continually recalculated while Fetch/movement hooks change hand size. Neither wrapper owns phase events or initial dealing. Source: [serverplayer.cpp:219–228](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.cpp#L219-L228) and [defaults, serverplayer.h:83–84](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.h#L83-L84).

## Draw phase is a separate owner

The GameRule EventPhaseProceeding case delegates to onPhaseProceed. For phase Draw, compute `2 + 3 * JieyueExtraDraw`, remove Global_FirstRound when present, emit DrawNCards with that integer and ignore consumption as an owner cancellation gate. Run freeChain, read the returned integer, call player.drawCards only if positive, run freeChain again, emit AfterDrawNCards with the **captured integer** even when nonpositive or no transfer occurred, then run freeChain a third time. The call supplies no reason argument, so the drawing reason/skill metadata is empty under ServerPlayer's default; do not inject a `draw` skill name. Changes to the game during drawing do not recompute the AfterDraw count. Consumption of the after event does not cancel additional work owned elsewhere. Safe normalized arithmetic/QVariant handling should be declared rather than emulating C++ overflow or Qt's arbitrary conversion coercions. Source: [gamerule.cpp:188–207](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L188-L207), [ServerPlayer default:serverplayer.h:84](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.h#L84), [EventPhaseProceeding:432–435](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L432-L435) and [one-shot SkipGameRule entry:262–270](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L262-L270).

There is **no removed-player guard** in these inspected Draw owners, and no phase-body alive recheck after DrawNCards; the later Room draw recipient check can prevent transfer if the player died. The full ServerPlayer phase wrapper skips EventPhaseProceeding when EventPhaseStart was consumed; it separately emits EventPhaseEnd only while alive. That wrapper is not implemented merely by adding a Draw-phase rule. Source: [Draw body](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L188-L207), [draw recipient guard](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4845-L4849) and [serverplayer.cpp:1133–1151](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.cpp#L1133-L1151).

freeChain is meaningful work, not a decorative no-op: it can kill a pending surrenderer, process general-show marks/events/reward entitlements and recurse. Including Draw phase therefore needs real registered freeChain composition or an explicitly scoped private operation adapter exercised at all three boundaries. A no-op test adapter cannot certify those native side effects. Source: [room.cpp:3174–3233](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L3174-L3233).

GameStart's global GameRule branch sets FirstRound=true and, outside custom_scenario, directly draws four for room.getPlayers(), then may ask for luck cards. It does not wrap that draw in the normal Draw-phase DrawNCards/AfterDrawNCards sequence. The selected native TriggerEvent list defines DrawNCards/AfterDrawNCards; do not import another engine's DrawInitialCards semantics into this owner. Initial setup/dealing/luck-card workflows and full turn execution remain a larger distinct scope. Source: [gamerule.cpp:321–327](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L321-L327) and [event definitions, structs.h:538–542](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L538-L542).

## Existing consumers do not all draw into hands

The native luck-card owner calls getNCards(false), then performs its own notifications, mappings and hand additions instead of generic atomic drawCards. Yiji acquires two IDs with update=false and delegates distribution to askForRende; Guanxing acquires IDs with default count update, privately logs them, then delegates rearrangement. getNCards must therefore remain an acquisition/result operation; automatically moving its result to a hand would break existing consumer contracts. These examples identify boundaries, not a new package audit or a claim those packages are ported. Source: [room.cpp:6305–6336](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6305-L6336), [Yiji, standard-wei-generals.cpp:434–440](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/package/standard-wei-generals.cpp#L434-L440) and [Guanxing, formation.cpp:507–520](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/package/formation.cpp#L507-L520).

## Bounded implementation alternatives

- **Primitive only:** getNCards atop actual draw/swap/reservation, tested through public dispatch/resume. Smallest change, but player draw/fill-hand still use external seams.
- **A — player drawing:** getNCards plus single/multiple-recipient drawCards, actual one-transaction movement and fill-hand composition. This completes the reusable acquisition-to-hand layer while leaving Draw phase, startup dealing and full turns separate. It is a coherent bounded next slice.
- **B — also Draw phase:** A plus the actual priority-zero Draw-phase handler, count marks/flags/events and all three explicit freeChain boundaries. Startup dealing/full phase progression stay excluded. This is also coherent, with freeChain's adapter/implementation boundary made explicit before claiming parity.

Initial dealing, luck-card behavior and full ServerPlayer::play/executePhaseEvent require separate specifications rather than silently entering A or B.

## Acceptance cases for the selected scope

1. Batch capacity before Fetch; pre-swap with remaining cards; insufficient capacity terminal before swap/count/fetch; zero/negative n with optional final count; ordered top/bottom IDs; ID zero; nested Fetch, intermediate terminal/interruption and exact prior-reservation retention.
2. Count and direction defaults; short count last-entry reuse versus short direction default=true; duplicates and skipped indices; alive/dead/reform/removed timing; malformed/null actors/count-list rejection; no invented recheck after a slot acquired cards.
3. All recipients reserve before one actual movement; last-recipient shortage leaves earlier reservations without hand transfer; BeforeCardsMove cancellation/rewrites; empty transaction through the real owner; nested draws cannot acquire reserved IDs twice.
4. DRAW actor/skill/eventName metadata; force=false/open=false normalization; current movement-wrapper and visible-flag policy; private recipient versus unrelated-viewer contract. Movement-owned count after source removal, no fabricated drawCards notice, and swap notice exceptions with update=false.
5. Fill-hand alive/deficit snapshot and no-op branches, including dead reform distinction and hand changes during children. Existing callers must compose actual drawing rather than substitute a callback that directly grants cards.
6. If B: actual EventPhaseProceeding Draw handler, SkipGameRule once, phase mismatch behavior, count mark arithmetic, Global_FirstRound clearing, rewritten/consumed DrawNCards, positive/nonpositive/dead/removed behavior, captured After count and three ordered freeChain children. Do not manufacture an extra removed guard.
7. Public JSON suspension/reload between each acquired card, recipient and real movement/event/notice boundary; wrong actor/stale/replayed/registry-mismatched prompts; prior eager results retained on interruption. No native exception cleanup/rollback or full-match reconnect claim.
