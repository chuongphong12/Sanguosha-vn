# SinglePeach to the Room use wrapper

Research dated 2026-10-21 against game baseline `c487311be37dbe47da35a438e8fdd29b02bdc85d` and native QSanguosha-QuocChien 2.3.43-beta2, commit `ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f`. This investigates the next bounded rescue composition after Part 4ab.3; it does not assert implementation, design approval, production enablement or native runtime differential validation.

## Finding

SinglePeach is a separate response-use owner. Its accepted card is already used inside `Room::askForSinglePeach`; the caller's AskForPeaches loop must not use it again. The required bridge is a registered Room operation retaining the accepted card's private reference and `addHistory=false`. It is not replacement with generic `askForCard(MethodUse)` or `askForUseCard` admission. Owning native code: [room.cpp:2003–2067](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2003-L2067) and [gamerule.cpp:664–688](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L664-L688).

## Request, conversion and retry

Each attempt first calls tryPause, sends focus for ASK_PEACH, then sets room current-card-use reason RESPONSE_USE. This owner does not set current-card-use pattern, emit CardAsked, consult a provided-card slot, set a continuing flag, or run the ordinary askForCard wrapped/log/reveal envelope. AI obtains a card from its own SinglePeach policy; human input receives `[dyingName, 1-currentHP]` and parses the first reply string. Failed transport, empty/non-string reply or null parsed card takes the nil decision branch. See [room.cpp:2005–2032](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2005-L2032).

Capture the original parsed card as `_card`. Apply `isCardLimited(card, MethodUse)` to that original card, then call its `validateInResponse(player)` only when nonnull and not limited. Unlike askForCard's distinct human/AI branch, this MethodUse limitation check applies to the selected human or AI result alike. Limited/null emits `ChoiceMade("peach:<dying>:<current 1-HP>:")` at the saver and returns null. A **validation-null** result instead recursively retries the same saver and dying pointer; it emits no ChoiceMade and no original-card after-hook for the failed attempt. The next attempt resets reason to RESPONSE_USE again. The native needed count in ChoiceMade is recomputed after input/conversion and may differ from the human request count. See [room.cpp:2034–2066](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2034-L2066).

MethodUse limitation includes package/card rules, e.g. SkillCard material limitations, physical unconverted Peach restriction in GlobalBattleRoyalMode, and removed-player restriction. These remain explicit private legality authorities; the bridge must not replace them with a generic inferred ownership check or claim to port the expression grammar. See [player.cpp:1744–1777](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.cpp#L1744-L1777).

## Accepted use and the two after-hooks

On nonnull validation, emit accepted ChoiceMade using the validated card string and the then-current needed count. Consumption or replacement of that decision payload does not redirect the captured saver, dying pointer, original or validated card. Then set `UsedBySecondWay` on the validated card, construct `CardUseStruct(card, saver, dying)`, call `useCard(use, false)`, call **the original raw card's `validateInResponseAfter(saver)`**, and return the accepted validated card. The bool returned by Room use is ignored: Room false still leads to that raw response after-hook and nonnull SinglePeach return. The accepted `const Card *` has no non-SkillCard restriction: a nonnull validated SkillCard can remain the accepted/returned identity and enter Room. There is no internal HP/alive recheck between accepted decision, Room use and after-hook. See [room.cpp:2051–2066](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2051-L2066).

The constructor supplies explicit card/from/one target, owner-use true and initial m_addHistory true. It does not initialize m_reason, m_isHandcard or index. A JSON port should preserve defined constructor defaults and omit unsupported uninitialized scalars, not invent native values for them. Room itself sets m_addHistory false and computes m_isHandcard. See [structs.cpp:238–260](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.cpp#L238-L260), [structs.h:97–123](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L97-L123) and [room.cpp:4187–4214](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4187-L4214).

The normal Room wrapper reparses its own card, copies incoming flags/tags, checks its own card-specific handling limitation, calls ordinary `validate(card_use)`, executes ordinary onUse and then ordinary `validateAfter(card_use)`. SinglePeach's earlier response conversion and later raw `validateInResponseAfter` are separate stages. Room null validation returns false without onUse; wrapper limitation also returns false. Both still allow SinglePeach's after-hook/nonnull return. See [room.cpp:4187–4269](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4187-L4269) and default hook definitions [card.cpp:984–997](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/card.cpp#L984-L997).

`addHistory=false` suppresses the **outer** Room history branch even if the saver is in Play phase. If ordinary Room validation converts to a different real card, native recursively invokes `useCard(new_use)` without passing false. The default argument is true. The converted child may therefore add history in Play phase; globally forcing false down all recursion would change the native contract. Native ignores the converted child's bool too, runs the original wrapper card's validateAfter with new_use and ultimately returns true. See [room.cpp:4234–4269](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4234-L4269) and [room.h:127](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.h#L127).

`setCardFlag` updates the supplied card and, for a physical card, its effective-ID resource and notification. Room parse/copy then sees the incoming flags/tags; converted package identities retain their own native authority rather than automatically inheriting every flag. SinglePeach keeps the accepted reference after Room finishes; later metadata/flags can change during shared CardFinished/resource cleanup and should not be frozen in a returned JSON descriptor. See [room.cpp:2440–2463](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L2440-L2463), [Room flag/tag copy:4191–4197](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4191-L4197), and [physical Parse result, card.cpp:659–669](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/card.cpp#L659-L669).

## Outer rescue loop and current dying identity

Room enterDying stores the original target independently of mutable Dying event data. Before each saver it rechecks original HP/alive, saves saver's `currentdying`, sets the original target name, emits AskForPeaches and restores the prior string. CurrentDying room tag is a separate nested stack/list. SinglePeach itself receives a stable dying pointer, not a dynamic lookup of whichever player was later pushed to CurrentDying. See [room.cpp:244–310](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L244-L310).

AskForPeaches snapshots Dying from event data once. Wansha eligibility and CannotHelp are tested once at this GameRule entry. While the captured dying player's current HP is nonpositive, current Peach prohibition/lock can break the loop; a living dying player is asked for one Peach; null result breaks; nonnull result loops back to inspect current HP. It does not require saver alive. It does not use the returned card again—the old use line is commented out. A nonnull but ineffective Room use may therefore lead to another ask. After the outer saver loop, AskForPeachesDone clears the first current CannotHelp flag and handles actual nonpositive/alive death through its separate rule. See [gamerule.cpp:664–707](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/gamerule.cpp#L664-L707).

Peach and Analeptic are concrete package behaviors, not part of the SinglePeach owner. Peach onEffect calls recover. Analeptic onEffect uses UsedBySecondWay to recover instead of adding drank. A library test can compose a clearly labelled package effect adapter with real movement/recovery; that does not enable the concrete packages. See [standard-basics.cpp:283–312](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/package/standard-basics.cpp#L283-L312) and [359–372](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/package/standard-basics.cpp#L359-L372).

## Web bridge design consequences

At this baseline, `src/game/hegemony/peach-response.ts` exposes `SinglePeachRules.use(use, false)` with a descriptor-only CardUse; the accepted registered `reference` is dropped at that seam. Actual `room-use-card` expects a `RoomCardUse` containing both use and reference, plus optional addHistory. Inferring arbitrary registered virtual/SkillCard identity from a descriptor is not a sound compatibility bridge. A direct registered Room child retaining the reference is the narrowest enforceable composition; alternatively an explicit full-entry adapter can retain compatibility at a documented API boundary, but must not bypass the Room owner. This is a design choice for the parent, not approval inferred by this note.

The old SinglePeach `validateAfter` policy name owns native **validateInResponseAfter**, not Room ordinary validateAfter. Keep those identities semantically distinct even if compatibility preserves the old property name. Despite its historical name, existing `readSlashCard` delegates to `readExecutionCardUse`, whose accepted types include `skill`; it already permits registered raw and validated SkillCards in both SinglePeach and the outer `dying-rule.ts` runAsk consumer. See [slash.ts:96–115 at the game baseline](https://github.com/chuongphong12/Sanguosha-vn/blob/c487311be37dbe47da35a438e8fdd29b02bdc85d/src/game/hegemony/slash.ts#L96-L115) and [card-on-use.ts:34–72](https://github.com/chuongphong12/Sanguosha-vn/blob/c487311be37dbe47da35a438e8fdd29b02bdc85d/src/game/hegemony/card-on-use.ts#L34-L72). The separate `readCardUse` rejects SkillCards, but readSlashCard does not call that narrower guard. Two public regressions composed by the parent with actual Room, SkillCard onUse, GameRule/effect and recovery pass before decoder changes; a missing SkillCard-decoder diagnosis was therefore rejected. No decoder broadening is required for that behavior. Reference retention at the descriptor-only use bridge and stale returned metadata are distinct issues, each reproduced by the parent's failing public regression. Return and hook metadata must preserve accepted/original reference identities while observing current resource flags. The game pin here identifies the local inspected baseline and does not assert remote publication of that branch.

## Acceptance matrix

1. **Actual dispatch:** public enter-dying/AskForPeaches → ask-single-peach → registered room-use-card → real onUse/GameRule/resources/movement/effect/recovery, with fixture package/admission authorities named. Assert one accepted card use, not a second use by the outer rescue rule.
2. **Bound reference/history:** physical and virtual accepted reference reaches Room unchanged, outer addHistory=false is explicit, owner/target defaults retained, saver in Play still does not add outer history. Include ordinary Room conversion whose child uses native default true and adds only the appropriate converted history.
3. **Three validation stages:** raw response validation → ordinary Room validation/onUse/ordinary after → original raw response after. Exercise response-validated identity different from original, Room-converted identity different again, and exact hook order/identity. Preserve the already-supported registered raw and validated SkillCard paths through both SinglePeach and its outer consumer; do not broaden an existing decoder without a failing behavior case.
4. **Failure distinctions:** input null/limitation emits nil ChoiceMade and returns null; response-validation-null retries same saver/target without decision/after for that failed attempt. Room limitation/null ordinary validation returns false, but accepted SinglePeach still calls raw response after and returns its accepted identity. The outer rule may ask again while HP remains nonpositive.
5. **Snapshots:** input needed count versus decision needed count after HP-changing conversion, response-use reset on each retry, no current-pattern overwrite, ChoiceMade mutation/consumption cannot redirect captured identities, no new internal HP/alive recheck after acceptance. Validate signed arithmetic safely rather than emulating native integer overflow.
6. **Flags/metadata:** UsedBySecondWay set before Room parse, wrapped and virtual resource ledgers, flags/tags preserved by normal wrapper, current flags observed after CardFinished/after-hook changes, accepted reference retained even when Room converted execution uses another card. Do not invent inheritance of flags onto unrelated converted cards.
7. **Outer guards and outcome:** multiple required Peaches, no-op/nonrecovering accepted response, refusal, current prohibition/lock, Wansha/CannotHelp, saver/target death, same captured dying identity versus nested CurrentDying and restored saver currentdying. Exercise successful real recovery and a failing-rescue path with the real death registry where within the approved test seam.
8. **Persistence:** suspend/reload at request, response conversion, ChoiceMade, Room ordinary validation, movement, shared events, recovery and both after-hook layers. Wrong actor, stale/replayed prompt and registry mismatch cannot double-spend or repeat recovery. Existing interruption policy retains eager state; no native unwind/rollback claim.
