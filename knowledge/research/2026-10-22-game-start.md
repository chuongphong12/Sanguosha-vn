Its qShuffle at line 4763 acts on a copy for AVAILABLE_CARDS, not the actual draw pile. Do not add a new real pile shuffle at this boundary by copying that statement literally. Full setup/application startup is wider than the global GameRule branch. ## Luck-card participant and request-round contract

askForLuckCard calls tryPause once, snapshots m_players entries whose getAI()==null, and clears their command arguments. getAI returns null for online state, the normal AI for robot/EnableCheat, and trust_ai otherwise; model the actual authority result rather than assume every non-robot is eligible. This initial list is not rebuilt each round, and the luck owner adds no alive/removed guard. Source: [src/server/room.cpp:6222–6237](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6222-L6237), [src/server/serverplayer.cpp:1299–1307](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.cpp#L1299-L1307).

For each iteration while n<limit: stop if remaining participants are empty; increment n; notify focus with the configured client command countdown; broadcast one LUCK_CARD request round. Retain only responses with ready=true and a strict boolean true payload. Missing, timeout/not-ready, malformed or false responses permanently remove that participant for later rounds; they are not retried as validation errors. Stop if no one accepted. Log #UseLuckCard for all accepted players, in retained list order, before returning any hands. The client presents an invoke/decline luck_card prompt, not a card subset chooser. Source: [src/server/room.cpp:6234–6265](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6234-L6265), [src/client/client.cpp:1208–1213](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/client/client.cpp#L1208-L1213).

doBroadcastRequest sends requests to every participant before waiting for any result. Its result loop shares a single elapsed server timeout budget, while focus uses the client command timeout. It is not a first-response-wins race, nor one complete timeout per sequential player prompt. doRequest resets reply readiness/payload and records command+serial; processClientReply rejects unsolicited, duplicate, wrong-command and wrong-serial packets. getResult supports OperationNoLimit and releases/finishes waiting on trust/offline transitions. A normalized engine can own round state while a batch request adapter owns simultaneous sending, deadline/authentication and normalized ready replies. Ordinary serial scheduler prompts cannot by themselves certify native broadcast timing. Sources: [src/server/room.cpp:763–810](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L763-L810), [src/server/room.cpp:972–1001](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L972-L1001), [src/server/room.cpp:4140–4185](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L4140-L4185).

## Luck-card physical return, shuffle and redeal

For each accepted player, capture current hand count immediately before that player's return, then return all hand IDs in hand-list order. Reason is PUT, actor=that player, skill=luck_card, empty eventName. Break down sources, send lose notice only to that player, remove the hand cards, run updateCardsOnLose, set owner=null/place=draw, run updateCardsOnGet, send get notice only to that player, then prepend each original ID to the actual pile. Sequential prepend reverses each returned hand chunk at the front before the later shuffle. Hand order comes from ServerPlayer::handCards, which iterates handcards. All accepted hands return before one shared shuffle. Source: [src/server/room.cpp:6267–6304](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6267-L6304), [src/server/serverplayer.cpp:578–584](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.cpp#L578-L584).

Next, in accepted-player order, acquire each captured count with getNCards(count,false), and manually complete that player's redeal before acquiring the next player's batch. These redeals are not Room::drawCards: their default CardMoveReason is UNKNOWN with empty string fields, not DRAW/luck_card. Send lose notices to ordinary recipients, remove IDs from available draw if still present, run updateCardsOnLose, set owner/player hand mapping, run updateCardsOnGet, send get notices, then add hand cards. Finally broadcast the current pile length once after all redeals in that round. A later acquisition failure retains earlier completed redeals; it is not a transaction across everyone. Source: [src/server/room.cpp:6305–6337](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6305-L6337), [src/core/structs.h:125–153](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L125-L153), [src/core/structs.h:250–259](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/structs.h#L250-L259).

It also lacks ordinary atomic arrival's explicit visible-flag clearing; preserving that distinction requires a scoped physical-transfer policy, not calling generic movement and assuming equivalence. Native return notices are private to the returning player; redeal notices use normal recipient-specific masking, including relevant actors, public places and Gongxin visibility, and skip offline recipients. Source: [src/server/room.cpp:6222–6338](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6222-L6338), [src/server/room.cpp:5733–5817](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L5733-L5817). Empty hands produce no broken-down card moves, but the owner can still perform an empty notice cycle, shared shuffle and count notice; do not assume no-op whole-round behavior just because a hand count is zero. ## Skill and package boundary

Player::getVisibleSkillList(include_equip=false) delegates to getSkillList(false,true). That list concatenates head_skills keys, deputy_skills keys, head_acquired_skills and deputy_acquired_skills, resolves each skill, excludes equipment skills and invisible skills under those arguments, and does not deduplicate the resulting list. It is not filtered by whether either general has been shown. Invisible related skills are added only when visible_only=false, which this startup call does not request. Therefore the catalogue adapter must supply the actual player-level combined/acquired visible list, preserving native order/duplicates; it must not substitute only the current/head general's skill definition. Sources: [src/core/player.h:308–314](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.h#L308-L314), [src/core/player.cpp:1499–1519](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.cpp#L1499-L1519), [src/core/player.cpp:1619–1627](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.cpp#L1619-L1627). hasLordSkill also queries current player hasSkill, not a public lord-role string: [src/core/player.cpp:572–577](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.cpp#L572-L577).

## Two coherent scope options

- **A — global GameRule owner:** implement the full normalized null-target branch with bespoke SkipGameRule bridge, staged lightbox/view/delay delivery, trusted visible-skill/lord eligibility and current-general/tag authorities, actual limited-mark writes, actual FirstRound tag, real draw-cards, and an explicit optional luck operation adapter. Luck-enabled fixtures prove delegation and resume only; the native luck algorithm remains unresolved. Call this the global GameRule GameStart owner, not all of Room::startGame/RoomThread startup. Per-player skill registration/startups and full turns remain separate.
- **B — A plus luck state/transfer owner:** additionally own the initial eligible snapshot, repeated batch-round survivor filtering, private returns, one shared shuffle, ordered captured-count get-n-cards redeals with their manual mapping/filter/notice lifecycle and final pile notice. A trusted batch-round adapter returns per-player ready/payload outcomes and owns simultaneous network send/common deadlines/authentication; it does not implement the luck selection/return algorithm. This is real normalized luck flow with explicit request/delivery authorities, not complete native broadcast transport or enabled whole packages.

Recommend A first if startup metadata/private delivery need a small independently validated seam; choose B only with the batch collection and manual transfer contracts explicitly accepted. A primitive that only deals four is a narrower alternative and must be named initial-deal-only rather than full GameStart. Neither option silently includes setup preparation, all package startup registration, first-turn orchestration, production registration or native unwind.

## Source-derived acceptance cases

1. SkipGameRule consumption before target guard; null versus player-targeted startup; repeated fresh events versus resume-once; event consumption in scheduler must not be confused with GameRule returning false.
2. Optional image/deputy-view branches, exact custom_scenario differences, fixed player order/next-alive private recipients, real delay placement; private general names never enter another viewer's payload.
3. Initialized-current-general precondition rejects missing general rather than skips; combined head/deputy/acquired visible skills; Limited/nonlimited/empty-mark/lord-ineligible entries and duplicate entries; mark set-to-one and owner-only notice ordering; no extra shown/alive filter or mark increment; immutable/trusted metadata contract stated.
4. FirstRound tag before real batch draw; four cards with empty reason; custom no default deal but still optional luck; terminal before all hands and eager state retained; no normal Draw events/free-chain invented.
5. If B: eligible snapshot, true/false/malformed/not-ready replies, zero/negative limits, participants drop permanently, mixed responses/round limits, changed connection or alive status, zero hands and no accepted users.
6. If B: all logs before returns, actual hand counts/order, all returns before one shuffle, deterministic portable RNG transcript, default UNKNOWN redeal reason, actual filtering/visibility distinction, private return versus masked redeal notices and latest final count.
7. If B: multiple redeals committing sequentially, later shortage leaves previous hands; nested Fetch during getNCards; per-card/boundary suspension; no generic movement events manufactured.
8. JSON reload/wrong/stale/duplicate/registry mismatch at every delivered child boundary; no native networking/timeout or complete-match claim from fixture adapters. Per-player package startup ordering remains a separately gated consumer unless explicitly included.
