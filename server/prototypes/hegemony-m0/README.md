# THROWAWAY M0 local tracer and bot baseline

Question: can an application-owned session stage the installed boardgame.io Master, commit its state and receipt together, then expose only actor views? Can a small actor-only TypeScript policy use that same command boundary?

This branch is an investigative source artifact, not a production implementation or a full Quốc Chiến match. The user approved the session contract at Q31 and continuing with a real Slash → Jink prompt. Its [contract](../../../knowledge/research/2026-10-22-m0-session-contract.md) and existing rules authority remain in force. These executable slices do not complete either M0.3 or M0.4.

## Run

- `npm run prototype:m0`: starts the loopback-only demo and prints its address and scratch-state path. Two private browser contexts represent different people; another tab of the same context can restore its stored seat. Restart with `npm run prototype:m0 -- /absolute/path/to/PROTOTYPE-wipe-me-…/rooms.json` to reuse that scratch state. The parent directory must exist. Delete that scratch directory when finished.
- `npm test -- tests/prototypes`: local kernel/session/privacy checks, including an actual killed server process.
- `npm run prototype:m0:browser`: installed Playwright Chromium, two isolated browser contexts plus a second tab, real HTTP/Socket.IO. This is separate from ordinary unit CI because it needs an installed browser.
- `npm run prototype:m0:benchmark`: emits raw local chooser and staged-Master draw measurements. Machine metrics are a baseline, not a latency/bot-strength acceptance threshold.

The demo needs its local server because real Socket.IO and disk recovery are the questions under test. It deliberately supersedes the prototype skill's default no-server/no-tests shape; the approved tickets explicitly require real transport/storage and privacy/fault checks. No production route imports this code. `server/server.ts`, existing engine modules and their registration are unchanged.

For Slash → Jink, seat 0 draws first (physical Slash 0), seat 1 draws second (physical Jink 1). Seat 0 chooses **Chơi Sát → Sát → 1 → Xác nhận**; seat 1 chooses **Thiểm** or declines, or the actor-only policy answers at the 60-second deadline. There is one Slash allowance in this fixed Play context, with 4 HP each and no turn advancement, equipment, conversions or skills. All fixture IDs are synthetic and are not a native deck manifest. The v3 clock save identity intentionally rejects older scratch saves; start a fresh scratch room.

## Clock authority and precision

Only the trusted session clock supplies monotonic time; clients have no tick/advance RPC. Deadlines and elapsed service time persist in the same document as engine effects. The default owner checkpoints at one-second scheduling intervals while rooms exist and checks due work before mutations. Actor views expose only their committed remaining decision time/control mode; callbacks and bot memory stay private. Timer-triggered publication is queued after durable commit.

Restart creates a new monotonic origin at readiness, never a wall-clock delta from the last save. Existing prompt/offline deadlines retain their saved service-time remainder; the room receives a fresh 60-second readiness recovery grace so retained humans can return. Any human return clears the all-offline room grace. Bot control does not count as an online human or preserve an abandoned room.

Only successfully checkpointed uptime survives a process stop. Uncommitted uptime may be given back, and background wakeup/commit/queue latency delays a timeout. The one-second scheduling interval is not a hard upper bound under storage/CPU delay. Failed writes publish no speculative result and retry later; failed recovery initialization releases the local writer lease. Exact crash-time accounting, provider availability/transaction semantics and production timing SLOs remain unproven.
