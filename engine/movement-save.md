## Cursor and physical packets

The decoder accepts a null initial frame or the actual persisted stages0–3 (BeforeCardsMove, ConfirmMoveCards, PreCardsMoveOneTime, CardsMoveOneTime). It validates integer actor progress and an ordered current-first subset of the captured actor list without repeating historical alive checks. A movement handler has no direct prompt/answer, operation child or cleanup cursor; nested skill prompts belong to their event/skill codecs. Its queued/completed event must have the stage name and captured target; a missing child is allowed only for genuinely abandoned unwind work.

Canonical moves and separated cardPackets validate aligned per-card arrays, safe unique physical IDs with one current ledger location, declared source/destination zone metadata, origin fields, visibility, last-hand/bottom flags and JSON reason. Source fields are historical: after a nested child or post event those IDs may be elsewhere. This is scoped validation against an already validated Room ledger, not a replacement for the aggregate ledger/catalogue validator.

Initial-stage packets bind to the original request through pure normalization on a cloned historical ledger: recorded moved sources are used and omitted same-zone no-ops are inferred at their destination. Later original request checks retain syntax and declared historical source hints without requiring the pre-commit location still be current. No real ledger, wrapper, notification, package rewrite, filter or interpreter work runs during decoding.

Stage0 has no separated packets. Later retained packets must each satisfy separation homogeneity (source owner/place/pile and visibility), retain current-first order and merge into the fixed physical batch. Validation acts on each packet separately; it must not re-separate the entire final list because overwritten incoming last-hand flags can leave distinct legitimate historical groups with identical final keys. Confirm/post notification JSON can change independently of this fixed physical batch.

A completion has exactly cancelled=true/moves=[] or cancelled=false/data (arbitrary notification JSON), plus a structurally valid original request. Validation cannot authenticate the original event history, reconstruct every package rewrite or prove a historical commit from untrusted state alone. Application persistence/profile/settings/root binding and content configuration remain separate requirements.

## Executed evidence and limits

[44 new cases](https://github.com/chuongphong12/Sanguosha-vn/blob/86dab10c58d808db8acf6adaf45d0221702da392/tests/hegemony/movement-save.test.ts) exercise real scheduler/movement/wrapper code through JSON/read/continue/resume/unwind. Budgets1/2/7/10000, prompts in all four phases, Before versus post consumption, pre/post commit interruption, nested actual movement with stale outer sources, mutable Confirm data, same-zone/no-op/bottom/discard/all-dead paths and corrupt cursors/metadata/child/results are covered. A hand exchange [0] from a and [2] from b ends at a=[1,2], b=[0]. Fixture observer/skill/event policies and wrapper filter eligibility are explicitly test adapters; the codec does not certify all enabled native packages or full matches.

[Player-draw recovery tests](https://github.com/chuongphong12/Sanguosha-vn/blob/86dab10c58d808db8acf6adaf45d0221702da392/tests/hegemony/player-draw-save.test.ts) now remove the boundary-only movement codec and stop skipping active movement checkpoints: acquisition through physical transfer is decoded with the actual handlers. This supersedes the earlier test-boundary limitation only at this source revision. Existing preflight/runtime callbacks, all17 prior movement helper ASTs and emitted scheduler interpreter remain unchanged. Whole Room/profile decoding, remaining startup/battle/package codecs, public v3 and release gates remain pending; PR33 stays draft.
