## Mandatory GameRule hand discard

This operation implements the nonoptional, hand-only gamerule call, not the generic all-purpose Room::askForDiscard with equipment/optional/skill variants. [Native Room](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/room.cpp#L6387-L6510) checks alive, sends focus, and gathers non-jilei hand cards. isJilei and focus are supplied package/presentation authorities. When legal cards are at most the required amount, move all of them immediately; zero returns true without a move or ChoiceMade. Otherwise the actor privately selects distinct legal cards and confirms. The authorized view exposes only the actor's own offered and partially selected IDs, required count and opaque tokens. Wrong actor, malformed, inherited, forged, stale, duplicate and newly illegal replies do not mutate state. The selection can be reset without moving cards. If legality changes after the prompt and fewer cards remain, the adapter recomputes requiredCount and asks for explicit confirmation, including an empty confirmation; that web recovery behavior is not a claim about a native interactive reset.

Actual move-cards moves the captured physical IDs openly to the configured discard pile with {kind:rule-discard, actor:target}. Each selected source zone is pinned before scheduling; movement rejects a card that left that zone rather than taking it from another player. A successfully returning movement child is followed by actual ChoiceMade with cardDiscard:gamerule:$<ids>. The saved selection is used even if movement is consumed/cancelled, because native throwCard is void and askForDiscard emits ChoiceMade afterward. The existing movement implementation owns event rewriting and pile ordering.

The trusted timeout method is fenced by the current prompt ID and is not exposed by the actor view or accepted by actor submit. It shuffles all current hand IDs using the persisted Room RNG, then filters current jilei and selects up to the original required amount, abandoning partial manual selection; this mirrors the ordering of native [forceToDiscard](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/server/serverplayer.cpp#L241-L260) with the project's portable RNG rather than C++ qrand bit parity. Timeouts and clock/deadline routing remain the application owner's responsibility. Do not expose raw scheduler frames, hidden timeout choice or this trusted method as a player command.

## Resume, ownership and scope

Continuations keep selected IDs, prompt generations, decision stages and token payment progress. JSON and bounded scheduler tests exercise nested choices/notices/movement and at-most-once RNG, movement, notices and ChoiceMade. Interruption abandons unfinished frames while preserving committed effects. Two tests intentionally inject an accepted-answer checkpoint; normal public resume executes its first operation step synchronously. A separate test injects an unauthorized source change after a yielded movement and verifies the source fence.

The single Room/scheduler owner must serialize mutations while work is yielded. The source-zone fence prevents taking a card from a different zone, but it does not re-evaluate jilei or death after the movement child has been scheduled. No existing consumer registers this new operation. Match-v3 must enforce sole state ownership, private routing, prompt/deadline fencing, recovery and trusted timeout access before it is exposed. This library slice does not prove all packages, real online sessions, full turns, a native executable differential or production readiness.
