## Profile opt-in and captured branch

PhaseBodyRules.saveProceeding:true is captured at factory construction. It enables save/result hooks only for phase-proceeding and changes that owner's post-dispatch cursor from true to exactly {child:name}, recording round-start-phase, judge-phase, draw-phase, play-phase or discard-phase. Profiles must version this opt-in and related trusted policy semantics. Default callers keep the original boolean cursor and no hooks; no old-profile migration or production registration is inferred. The factory's RoundStart/Judge handlers still have no codecs, so enabling the option does not imply whole-factory coverage.

Input uses the immutable ruleInput contract: known original target or null, with the existing ignored inner payload. Own prompt/answer/event result/cleanup reject. A null initial cursor cannot have a queued/retained child; decoding does not run the live phase gate. A resumed cursor requires a nonnull input target and exactly one supported captured child name. Queued/retained operations must match that name and exactly target/data keys, with original target and null data. Missing children are accepted only for actual abandonment. Retained owner results must be null, with valid immutable input.

The decoder never selects a branch from current playerPhases, resolves card metadata or calls onNullified. Changing phase after dispatch does not reroute Proceeding; each child retains its own native entry checks. Once the actual Draw owner has captured its count, a later phase change does not replay or replace its work. At an unstarted Proceeding frame, phase none remains structurally readable and throws the existing Invalid Proceeding phase only when live execution reaches that gate. Aggregate Room validation is still separate.
