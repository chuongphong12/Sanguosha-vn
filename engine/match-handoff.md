# Trusted startup-to-battle handoff

M1.3.5b adds [handoffMatchTurn](https://github.com/chuongphong12/Sanguosha-vn/blob/1cf3b03c53b54e4b74fc8bf85c52be884fccc122/src/game/hegemony/match-handoff.ts) at game 1cf3b03c53b54e4b74fc8bf85c52be884fccc122, fixed base d20092745fa4e3e9e98440dbab1e173b8a2825c1. It consumes an already validated mutable match-v2 prepared candidate and constructs the internal v3 battle branch. Existing createHegemonyMatch, startup, scheduler, M0, server and production registration are unchanged. This is not a complete public match-v3 create/apply/view/restore implementation. See [checkpoint](../reviews/2026-11-12-hegemony-m135b-handoff.md) and [accepted B design](../specs/hegemony-turn-unwind.md).

## One authority and a static table switch

The precondition is a nonterminal Room branch at startup complete, using that match's startup-full table, with no frames, prompt, interruption, cooperative yield, unwind or pending operation/unwind completion. The retained root completion must be GameStart for a registered player or the global null target. The battle table must differ from both startup-global and startup-full. A bounded opt-in turn owner, unique operation/skill IDs, declared priority-zero TurnStart/phase-cleanup/phase-Proceeding rules and absence of the standalone Draw rule are checked before transfer. This verifies the declared core table shape, not arbitrary callback/package semantics.

Handoff does not dispatch a turn, deal again, shuffle or allocate scheduler IDs. Preflight builds only a validation image and runs the existing trusted turn-owner validator. After validation it commits missing battle maps onto the same Room object, changes the same scheduler's registry identity, and clears the consumed startup completion. The returned branch owns those same objects. The caller must replace its current root and discard the old v2 wrapper; its startup table is consumed and a repeated handoff fails. Cross-revision command idempotency or durable publication is a later session responsibility, not a global guarantee supplied by this function.

Room.currentPlayer, current not-active phases, HP/life, identities, cards/wrappers/resources, marks/history and saved RNG are retained. Missing faceUp defaults to true as [native Player::Player](https://github.com/TamQuocSat-LangKhach/QSanguosha-QuocChien/blob/ce4e62b31c4d1a65de79188be11ccdd4f0ac6f9f/src/core/player.cpp#L37) does. Missing phase queues, typed mark/limitation ledgers, normal-turn cursor and Engine-card flags are initialized. Valid pre-existing ledgers, face-down state and Engine flags are preserved by reference; they are not reset. The initial normal-turn cursor must be regular with null anchor. Existing optional undefined limitation patterns remain valid, matching the actual limitation authority.

The supplied ordered physical catalogue IDs are copied. They must be unique nonnegative safe integers and cover Room physical inventory/wrappers; inventory cannot duplicate an ID. Catalogue-only disabled physical IDs may have Engine flags without a Room zone or wrapper. Engine flags remain distinct from wrapped flags. This does not reconstruct initial C++ shuffle or certify a package-enabled catalogue; the versioned profile supplies that authority.

## Internal v3 branch and persistence limits

The branch records schemaVersion hegemony-match-v3, phase battle, inherited rules/content/startup identities and settings, startup complete, the new registry/stepBudget/catalogue identity and the trusted turn cursor. Registry callbacks are not serialized. This is an internal constructed branch, not a public restore contract. Do not pass it to the old v2 restore/view methods.

Tests serialize this branch and continue it through createMatchTurn.validate/advance plus known admission/prompt routes. That proves the stated internal continuation, not comprehensive untrusted JSON validation, authentication, private v3 projection or a crash-safe application/store transaction. Those public seams, save/profile binding, startup interruption ownership and minimal-profile combat-to-terminal scenarios remain required next.

## Executed evidence and profile limits

[49 new cases](https://github.com/chuongphong12/Sanguosha-vn/blob/1cf3b03c53b54e4b74fc8bf85c52be884fccc122/tests/hegemony/match-handoff.test.ts) start from public paired setup and actual startup/dealing. They transfer once without changing Room/scheduler/RNG/nextId, complete a real first turn for every2–10-seat count, continue JSON with budgets1/7/10000, wait for two actual per-player startup prompts, preserve trusted preinitialized conditions, fence selected malformed inputs without mutation, and cover catalogue copying/disabled IDs and reserved table identities. A separate offered RoundStart head reveal executes actual show-general before completing the turn.

The default first-turn cases cancel reveal and decline Play in an all-Jink synthetic content profile. Real setup/startup/get-winner nonwinning branch/drawing, turn/phase/reveal/admission/discard/movement/free-chain/cleanup operations run. Content metadata, general eligibility and presentation/filter hooks, card offers, maximum/Jilei and startup prompt listeners are explicit fixtures. The preinitialized face-down/ledger case and malformed-save cases inject trusted conditions. Reward-rule/package interactions, native executable parity, actual card-use/Slash/damage/rescue/winner, a complete match, bots, UI, transport/storage/provider/load and production cutover are not established by this slice.
